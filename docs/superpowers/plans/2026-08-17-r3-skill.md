## Task 2: `SKILL.md` — mental model, surface strategy, lifecycle

**Files:**
- Modify: `skills/r3/SKILL.md` (sections 1–3)

- [ ] **Step 1: Author section 1 — mental model** (source: findings §A; spec §3.1)

Must include, terse:
- A job is a directory; `commit` freezes the *recipe* (code + resolved deps) by content **hash for
  integrity**; **identity is a fresh `uuid4`, not content-addressed** (identical recipes → different ids).
- Immutable after commit **except `metadata.yaml` and `output/`**. **`output/` is the one place results
  persist** (writing elsewhere in an in-place run → `PermissionError`).
- **r3 is not an execution engine** — its only runtime touchpoint is `r3 checkout`; running is your code;
  `run.sh`/`commands:` are not r3 concepts (a `commands:` key is inert).
- The job dir is **free-form** — every non-ignored file freezes (configs, notes, specs), not just code.
- Provenance = deps frozen (git commit hashes, job uuids) at commit → **reorganize `path`/tags later
  without breaking committed jobs** (metadata is mutable + not hashed; deps pin uuids).

- [ ] **Step 2: Author section 2 — surface strategy** (source: spec §4; findings §B/§I)

Must include:
- **CLI-first for the lifecycle verbs** (permission-bounded: allowlist `Bash(r3 …:*)`); verbs: `init`,
  `commit` (prints bare uuid), `checkout <id> <path>`, `remove <id>`, `find` (tag-only), `rebuild-index`,
  `edit <id>`. Reads `R3_REPOSITORY` (or `--repository`); `R3_REPOSITORY=""` counts as missing.
- **The Python API is r3's general interface to the job graph — for reading AND reshaping it** (open-ended;
  ONE loose example only, e.g. "find every job, in any dependency order, that transitively uses repo X at
  commit Y"; do NOT enumerate a closed list). Entry points: `r3.Repository(path)` (`find`, `checkout`,
  `commit`, `remove`, `find_dependents`, `jobs`, `repo[id]`) and `r3.Job(dir)`.
- Two capabilities to name clearly, **as ordinary prose/headings — never as `‹…›` tokens** (they're the
  two beats an environment's own docs may point at by plain name): **querying beyond tags** (CLI `find` is
  tag-only → use the API / `find_latest` for path / metadata / `$glob` queries; a JSON-query CLI option is
  planned upstream) and **dev checkout** (running a job before committing it — deliberately user-owned; see
  the lifecycle section + `scripts/r3dev.py`).
- Details → `reference/python-api.md`.

- [ ] **Step 3: Author section 3 — lifecycle** (source: findings §A/§D/§E/§H; spec §3.3)

Must include:
- Author a job (`run.py`; `r3.yaml`/`metadata.yaml` optional — synthesized at commit).
- Run: **in-place** for a dependency-free job (`cd jobs/<id> && python run.py`); once it has deps, **`r3
  checkout <id> <workdir>`** first (the workdir is **throwaway scratch** — only its `output/` symlink
  persists to the store; the target must not pre-exist).
- **Dev-checkout** = running an *uncommitted* job: r3 removed the CLI command on purpose; the primitive is
  `repo.checkout(unresolved_dep, dir)`; the bundled `scripts/r3dev.py` is the ~25-line reference loop. A
  dev checkout materializes only deps (no `output/` symlink) and **cannot change what you commit**.
- Update an outdated job: **re-commit** (re-resolves `find_latest`/`find_all` to current).
- `remove` refuses (nonzero exit) if any job depends on it; reclaim disk by deleting `output/` (record it
  in `metadata.yaml`). `rm -rf` on a committed job fails (`555`) — use `r3 remove` or `chmod -R +w` first.

## Task 3: `SKILL.md` — dependencies, query grammar overview, metadata & path

**Files:**
- Modify: `skills/r3/SKILL.md` (sections 4–5)

- [ ] **Step 1: Author section 4 — dependencies** (source: findings §C/§D/§E/§N/§O; spec §3.4)

Must include, terse:
- **Git dep:** `{repository, destination, source?, branch?/tag?/commit?}`; **github.com only** (https or
  ssh); no pin → resolves to the remote's **default-branch HEAD** at commit and **freezes the 40-hex
  `commit:`** (branch/tag don't round-trip); cached as a bare clone in `<repo>/git/github.com/<o>/<n>`.
- **Job dep:** `{find_latest|find_all: <query>, destination, source?, recursive_checkout?}` — resolves at
  commit and keeps **both** the loose query and the resolved `job: <uuid>`. Materialization: `source: "."`
  + `recursive_checkout: true` (defaults) → a **recursive real copy** (incl. the dep's own transitive
  deps); otherwise a **symlink** (`source: output` → symlink to the upstream `output/`; a non-`.` source
  is always a symlink). So `source:` is **scope, not duplication**.
- **Reading old recipes:** the deprecated **string form `query: '#tag #tag'`** is common in older jobs —
  recognize it; steer new jobs to `find_latest`/`find_all`. Dep constructors in the API are
  **destination-first** (see `reference/python-api.md`).
- **`ignore`** (absolute, exact-segment patterns only — `/output`, `/cache`; no globs, no `.gitignore`):
  `output/` is excluded from every commit **unconditionally** anyway; use `ignore` for other non-output
  artifacts (report renders, caches, `__pycache__`).

- [ ] **Step 2: Author section 4 — query grammar OVERVIEW** (source: findings §F/§N/§O; spec §6)

One paragraph + pointer. Must state: Mongo-style but **only a subset**; logical `$and/$or/$not/$nor` +
implicit-AND; conditions `$eq`(implicit)`/$ne/$in/$nin/$gt/$gte/$lt/$lte/$glob/$all/$elemMatch`; `find({})`
= all. **Full grammar, array semantics, and the sharp gotchas → `reference/query-grammar.md`.** (Do not
inline the gotchas here.)

- [ ] **Step 3: Author section 5 — metadata & `path`** (source: findings §G/§O; spec §7)

Must include:
- `metadata.yaml` is mutable, **not hashed**, must be **JSON-representable** (a bare YAML date → `TypeError`
  at commit — quote dates). Edit via `r3 edit` or edit-file + `rebuild-index`.
- **`tags`** is the only field r3's *tooling* privileges today (`find --tag`, `#tag` rendering).
- **`path`** is the recommended organizing convention — a virtual-filesystem path that
  `find_latest`/`find_all` build on; queryable like any metadata field, but not yet surfaced by the CLI
  (`--path`/`r3 ls` are planned). Convey as EXAMPLES, not rules: flat (`kodak`), nested
  (`datasets/kodak`, `my-project/experiments/pilot`); path can be shared by a sweep (`find_latest`→newest,
  `find_all`→all); path is a **movable namespace** (re-path later; frozen deps unaffected). Note groups
  often prefix paths with a project name for global uniqueness — offer it as one option, not a mandate.

## Task 7: `reference/query-grammar.md`

**Files:**
- Create: `skills/r3/reference/query-grammar.md`

- [ ] **Step 1: Author the grammar reference** (source: findings §F/§N/§O; spec §6)

Must include, complete and exact:
- **Logical:** `$and`, `$or`, `$not`, `$nor`, implicit-AND (a multi-key dict). Unknown `$op` at query level
  → `ValueError`.
- **Field conditions:** `$eq`(implicit)`/$ne/$in/$nin/$gt/$gte/$lt/$lte/$glob/$all/$elemMatch`.
- **Not implemented — do NOT advertise:** `$exists/$type/$regex/$size/$mod/$expr/$text`, and **field-level
  `$not`**. **Unknown FIELD-level operators are SILENTLY coerced to `$eq`** (no error) — a silent-wrong
  trap. A scalar field can't carry two operators (`{f:{$gt:1,$lt:9}}` → error) — use `$and`/`$elemMatch`.
- **Array semantics (the sharp ones):** `$eq`/implicit/`$in`/`$glob` on an array = "contains"; **`$ne`/`$nin`
  on an array do NOT exclude** (match if any element differs → basically all rows); `$all`/`$elemMatch`
  are **JSON-type-strict** (`28` ≠ `"28"`); `$elemMatch` binds all sub-conditions to ONE element; empty
  `$all` = match-all.
- **`$glob`** = SQLite GLOB (case-sensitive, `* ? [..]`), not regex/LIKE.
- **Ranges on strings:** values interpolate **unquoted** → numeric-parseable value matches all/none by type
  ranking; a non-numeric token errors. Store numeric versions; use `$eq` for strings. Query values aren't
  parameterized — embedded quotes break.
- **Dotted nested fields** work: `{"task_meta.seed": 42}` → `metadata->>'$.task_meta.seed'`.
- **Ordering:** results are **unspecified** unless `latest=True` (→ newest by timestamp).

- [ ] **Step 2: Verify against `main` + a quick live probe**

- `grep -n "def to_sql\|Eq\|Ne\|Gt\|Glob\|All\|ElemMatch\|from_mongo" /tmp/r3-main/r3/query.py` — confirm the

- (Optional, high-value) build a throwaway repo, commit two jobs with numeric + string metadata, and probe
